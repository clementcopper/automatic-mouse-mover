# Session — 2026-08-27

Continues 2026-08-26. Started as "AMM crashes on Apple Silicon and Intel", ended with a
dependency-free 1.6.0 verified on both architectures.

## Decisions

- **Crash root cause was in robotgo**, not in AMM: an uninitialised `MData` returned by
  `get_active()` when no front process exists (lid closed, screen locked). Fixed not by
  patching but by deleting the code path — `activity-tracker`'s `GetTitle()` poll is gone.
- **Every runtime dependency removed.** robotgo, activity-tracker, mac-sleep-notifier and
  systray replaced by ~250 lines in `internal/mac`. `go.mod` keeps only testify, tests
  only. Deliberately kept: testify stays, the bundle id stays `com.pg.amm` (renaming would
  invalidate the Accessibility grant and login item again).
- **No sleep detection.** Clamshell is exactly when AMM should keep working, so a
  `CGDisplayIsAsleep` guard was dropped after Daniel pointed out the case.
- **Attribution**: About and README name Daniel first, original by Prashant Gupta named
  underneath, `LICENSE` carries both copyright lines.
- **Icon**: one SVG, embedded via `//go:embed tray.*`, drawn as a template image so macOS
  tints it. Not square — scaled to 16 pt tall with the width following.
- **Version 1.6.0 released**, built and attached by the new CI workflow on tag push.
  v1.5.0 and v1.4.0-rc1 deleted; exactly one tag and one release remain.

## What was verified, and how

- Cursor moves on schedule: idle sawtooth measured, resets only above the 60 s threshold.
- `CGEventPost` resets the system idle timer — idle went 644 s → 0.03 s across one
  self-posted move. That is the wake-keeping mechanism.
- Binary 3.37 → 2.15 MB per architecture with `-s -w`; panic traces byte-identical.
- Release artefact downloaded, installed and run on Intel. Apple Silicon confirmed by
  Daniel: app runs, Teams stays active.
- Menu, greying, light/dark icon tinting: confirmed by Daniel by eye — no script can see
  them, AppKit resolves both at display time.

## Bugs I introduced and then found

- `moveAndCheck` read the cursor back before the posted event landed: **20 of 20 moves
  counted as failures**, and the pointer drifted into a corner because the sign only flips
  on success.
- The os_log handler first used `OS_LOG_TYPE_INFO`, which macOS does not retain — only
  errors appeared, i.e. exactly the blind spot it was meant to remove.
- Silencing test logging through a package-level var was a real data race.
- A scripted `replace` silently matched nothing twice (once after gofmt normalised
  comments, once after a `sed` had already rewritten the target string).
